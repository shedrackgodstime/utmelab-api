build-a-cbt-session.ts 
// npm i @acada/sdk
import { Acada } from "@acada/sdk";

const acada = new Acada(process.env.ACADA_KEY);

// Pull verified JAMB questions by topic
const questions = await acada.questions.list({
  exam:    "jamb",
  subject: "mathematics",
  topic:   "quadratic-equations",
  limit:   20,
});

// Spin up a timed CBT session
const session = await acada.assessments.create({
  learnerId:    "lrn_8f2c91",
  questions:    questions.map(q => q.id),
  durationMins: 30,
  shuffle:      true,
});

The problem

Every education team in Africa rebuilds the same foundation.

Educational content is scattered, assessment logic gets rewritten from scratch, and student data lives in a dozen incompatible formats. The result: months of engineering spent on plumbing instead of on learning.

Content is scattered

Past questions live in PDFs, WhatsApp groups and photocopied booklets. Nothing is structured, versioned or searchable — so nothing can be built on top of it.

The same engine, rebuilt

Timers, shuffling, grading, scoring, result retrieval, session recovery. Every CBT product writes this from scratch, badly, and pays for it in outages.

Data that can't talk

One school uses spreadsheets, another a legacy portal, a third a homegrown app. Integrating them means writing a new adapter every single time.

Trust

Student data is not a growth metric.

We handle records for minors. That shapes every design decision we make — what we store, who can read it, and how long we keep it.

NDPR-aware by design

Data minimisation, purpose limitation and clear retention windows built into the platform, not bolted on.

Consent-based access

Learner-level records are only shared with explicit, revocable consent from the right party.

Aggregated by default

Analytics endpoints return cohort-level insight unless you're explicitly authorised for individual data.

Traceable content

Every question carries its source and license, so you can defend your product commercially.
