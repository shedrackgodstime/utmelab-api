# Proposal: short topic descriptions for study browsing

**Status:** Consumer-driven proposal; needs API maintainer review
**Raised from:** UtmeLab's topic-card study browsing
**Date:** 2026-11-20

## Summary

Expose an optional, concise topic description alongside the syllabus topic name.
This copy is for compact topic cards in a study browser; it is not a replacement
for the board's syllabus objectives or subtopic tree.

## Current observed contract

`GET /api/v1/subjects/{exam}/{slug}/syllabus` serves ordered topics with
`slug`, `name`, `order`, `weight`, `question_count`, `objectives`, country
scope, note indicators, and nested subtopics. There is no dedicated short
description field on a topic or subtopic. `objectives` are syllabus statements,
not descriptions written for a compact browse card.

Topic notes are a separate optional content resource; their availability does
not provide a short description for every syllabus topic.

## Consumer problem

UtmeLab's study browser currently presents the first syllabus objective as
though it were a topic description, then lists the remaining objectives and
subtopics on the same card. That makes a topic-selection list read like an
expanded syllabus and obscures the topic title and next action.

The app now keeps topic cards concise, showing the topic name and compact
question/subtopic counts. It does not derive or invent descriptions from
objectives. The API field and app data mapping must both be added before cards
can display a real short description.

## Proposed contract direction

Add a backward-compatible optional `description` to syllabus topics, and
consider the same field on subtopics only if there is a supported consumer
need:

```json
{
  "slug": "momentum",
  "name": "Momentum",
  "description": "How moving objects transfer motion through collisions.",
  "objectives": [],
  "subtopics": []
}
```

The example is illustrative, not authored curriculum copy. Requirements:

- The field is a short plain-text overview suitable for a topic card (suggested
  maximum: 160 characters).
- It is distinct from board-authored syllabus objectives and must not be
  generated by truncating or concatenating them.
- It is optional and omitted when no source-backed or editorially reviewed
  description exists; existing consumers remain compatible.
- Its authoring/source policy is explicit. If editorially authored, preserve
  that distinction from official board statements.
- Topic order, objectives, country scope, subtopics, and live question counts
  keep their existing meanings.

## Suggested implementation investigation

1. Confirm which catalog source owns the topic tree and where short descriptions
   can be authored and reviewed.
2. Decide whether descriptions are appropriate for all topics or only topics
   with an approved source-backed overview; do not fill gaps with generated
   syllabus paraphrases.
3. Add the field to the authoritative source and storage/import pipeline only
   after the source policy is clear.
4. Project the optional value through authenticated and public syllabus
   responses, as applicable, and update OpenAPI.
5. Test old source records without descriptions, new records with descriptions,
   and unchanged objective/subtopic behavior.

## Acceptance criteria

- A consumer can render a concise topic overview without treating syllabus
  objectives as display descriptions.
- Missing descriptions remain a normal absence and do not break older clients
  or content records.
- No description is fabricated from objectives or other unrelated content.
- API documentation distinguishes topic descriptions from objectives and
  topic notes.
